Overview

Build a reusable research runtime implementing the autoresearch loop — baseline → constrained mutation → reproducible experiment → objective evaluation → keep/revert → durable record → repeat — and apply it across the whole project portfolio, not just ML training.

Thesis: any project becomes a candidate for autonomous research once we can define an experimental artifact, an isolated evaluator, measurable outcomes, and boundaries on what the researcher may modify. The hard engineering problem is not the researcher — it is evaluate(). A weak evaluator trains an agent to game the benchmark; a strong evaluator trains an autonomous engineer.

Prime directive: the research agent never controls the evaluator. Evaluator code, hidden datasets, and promotion corpora sit behind an immutable boundary enforced by real sandboxing, not convention.

Goals & Non-goals

Goals

  • One reusable runtime: experiment spec, isolated candidate runner, immutable evaluator, JSONL history, leaderboard, keep/revert, seed & resource accounting.
  • A universal per-project contract (research.yaml + autoresearch/ layout) that works for Python, Rust, Go, prompts, netlists, scenes, geometries.
  • Hard gates first; metric vectors preserved; Pareto archive; variance penalties; hidden promotion corpora; resource cost as a first-class metric.
  • Durable experiment records that become institutional memory (eventually a knowledge graph).
  • Explicit anti-reward-hacking posture: per-environment THREATS.md, exploits become regression tests.

Non-goals (v1)

  • No multi-agent research org (Director / Literature / Analyst split) until Phase 1 environments have run for weeks — one agent, one loop.
  • No meta-research (optimizing the researcher) until environments are trustworthy.
  • No Pareto-based promotion decisions in v1 — Pareto is an archive; promotion is a declared scalar (see Review F2).
  • No learned/human-preference evaluators in early phases; start where ground truth is crisp.
  • No autonomous experimentation on live users (curriculum work runs on simulation/retrospective data only).

Universal research contract

Each participating project ships an autoresearch/ directory: objective.md, research.yaml, candidate/ (mutable), evaluator/ (immutable: gates, metrics, scalarize), layered datasets/ (development / validation / hidden), scenarios/, baselines/, results/ (experiments.jsonl, leaderboard, artifacts).

research.yaml example (stereo-3dgs)
name: stereo-3dgs
mutable:   [pipeline/**, configs/**]
immutable: [autoresearch/evaluator/**, autoresearch/datasets/hidden/**]
command:
  candidate: ./run_candidate.sh
  evaluate:  ./evaluate.sh
resources: {gpu: 1, max_vram_gb: 11, max_cpu_threads: 8, max_disk_gb: 30}
gates: [valid_output, no_test_view_leakage, calibration_valid]
promotion_score: psnr_minus_lambda_vram   # v1: one declared scalar (Review F2)
objectives:
  psnr:          {direction: maximize}
  lpips:         {direction: minimize}
  train_seconds: {direction: minimize}
  peak_vram:     {direction: minimize}

Evaluation philosophy

  • Hard gates first — validity is never tradable (solvable level, passing ERC, reconciling workbook, importable mesh). Gate failure ⇒ invalid, no rescue by quality.
  • Metric vectors, not one number — full vectors persist in history; scalarization only at promotion time.
  • Pareto archive — track dominates(a,b); keep the frontier as institutional record.
  • Variance penalized — track mean/median/σ/p05/p95/worst; promote on mean − λσ or p10 where worst-case matters.
  • Hidden promotion evaluation — development (visible) / validation (evaluator-only) / promotion (fully hidden, rotated).
  • Repeated seeds — paired seeds vs champion; reject noise-only wins (Review F4).
  • Resources are performance — wall clock, GPU/CPU time, VRAM, disk, API cost, tokens on every record.

Env 0 — nanochat speedrun (this repo)

Mutable: train.py only. Gate: run completes within 5-min budget, no NaN. Metric: val_bpb ↓ (already scalar). Role: validate the harness contract against a known-working loop before any new evaluator is written — the harness must reproduce what the bare Karpathy loop already does, with history/leaderboard/keep-revert on top.

Env 1 — LevelForge → PlayTrek worldgen (live)

Update 2026-08-30: the LevelForge generator described below lives on as PlayTrek; the shipped environment is playtrek-worldgen — world-genesis prompt/loop as candidate, the hallMonitor evaluator suite as frozen evaluate(). First promoted experiment 00009 (role-voice prompts + response repair): worldgen_mean_score 0.874→0.921 over the 4 responsive evaluators; npc-consistency 0.53→0.70, world-coherence 0.99. Structural ceilings (standards-alignment, narrative-integration — the wrap emits no waves) are excluded from the promotion scalar. En route, the gates caught two evaluator false-positive families ("bet"/"race"/"shoot" keyword collisions) worth fixing upstream. The planner-based solvability metrics below remain the target for episode-level (not world-level) evaluation.

Mutable: NL constraint extraction, generator, tile weighting, constraint solver, difficulty controller, candidate selection. Gates: schema valid · rules satisfied · initializes · solvable (deterministic planner, not RL) · no unreachable required state.

v1 metrics (computable): solvability, difficulty error (|requested − measured| from optimal solution length / nodes expanded / branching factor), instruction coverage against parsed requirements. v2 metrics (research-grade, not gating): pedagogical alignment, solution diversity/entropy, cross-level diversity, controllability (Review F9). Benchmark: hundreds of prompts spanning simple, contradictory, multi-domain, difficulty-targeted, negative-constraint requests.

Env 2 — Stereo → 3D Gaussian Splatting

Mutable: stereo matching, depth confidence filtering, pose refinement, Gaussian init, losses, LR schedules, densification/pruning, SH degree, regularization, iteration count. Gates: camera model valid · held-out cameras excluded · render completes · no NaNs · sane scene bounds.

Quality: PSNR↑ SSIM↑ LPIPS↓, depth error↓, multiview consistency↑. Efficiency: train seconds↓, peak VRAM↓, Gaussian count↓, FPS↑. Permanent stereo benchmark: tabletop, PCBs, rooms, outdoor, vehicles, vegetation, thin geometry, reflective, low-texture — some with measured depth ground truth. Budget honestly: a benchmark sweep × seeds is hours per experiment on a 4070 (Review F1).

Env 3 — Veritas ProtocolGym ✓

ProtocolFactory procedurally generates protocols (sync words, TLVs, bitfields, CRCs, counters, sessions, state machines) + reference implementations + traces. Only the evaluator sees the spec; Veritas sees raw observations. Metrics: message-boundary F1, field-boundary/type F1, derived-field detection (length/CRC/counter/timestamp), message clustering, state-machine precision/recall, parser generalization on unseen traffic, serializer accepted-by-hidden-reference (strongest oracle). Extensions: active RE (info gained per probe), logic-analyzer waveforms (UART/SPI/I2C-like).

Env 4 — TaxLens

PDF → structured workbook. Gates: schema valid, required worksheets, numeric types, identifiers preserved. Metrics: per-field exact/normalized/tolerance match; reconciliation identities (subtotal == Σchildren, tax_due == liability − payments, schedule == summary) as the strongest evaluator; grounding (source page/region/text entailment). Hallucinated fields cost far more than omissions.

Env 5 — Video → Mocap

Gates: valid connected skeleton, physical bone lengths, monotonic timestamps, animation imports. Metrics: MPJPE↓, PA-MPJPE↓, reprojection error↓, foot skating↓, contact error↓, penetration↓, bone-length variation↓, jerk↓. Ground truth from mocap datasets, synthetic Unity animation, multi-camera references. Mutable: pose model config, temporal model, filtering, IK, contact detection, root motion, retargeting.

Second/third-wave evaluator sketches (S / A / B tiers)
  • FabForge: ERC + protection gates; scenario sim (voltage extremes, surge, faults); minimize cost/mass/losses/voltage drop; serviceability scores.
  • COI: field accuracy, requirement satisfaction, endorsement & contradiction detection; "is this vendor compliant, why, what's missing" against ground truth.
  • OT analyzer: synthetic industrial labs (Modbus/EtherNet-IP/BACnet/S7/OPC-UA); asset & topology P/R; anomaly TPR vs FP/day; hard gate: zero transmitted packets, verified by evaluator.
  • ASTERIX: decode/roundtrip accuracy on synthetic airspace; tracking RMSE, ID switches; msgs/sec.
  • 3D assets / voice: staged gates (import, UV, rig test-suite; WER, speaker similarity transfer, MOS predictors) — needs human-correlation program (§Eval of evaluators).
  • Driftport / startup research / streaming / QSR / poker / chess / radio: graph P/R vs annotated corpus; historical-snapshot reconstruction + falsification agent; network-sim video QoE + bandwidth cost; ops simulator profit objective; EV regret vs solver; centipawn loss; synthetic RF scenarios.
  • CFD: multi-fidelity ladder — geometric heuristic → surrogate → coarse CFD → fine CFD → physical scale test.

Anti-reward-hacking

  • Every environment maintains autoresearch/THREATS.md (e.g. 3DGS memorizing validation views; LevelForge trivially-solvable levels; TaxLens hardcoded common values; Veritas recognizing generator seeds; FabForge deleting loads).
  • Every discovered exploit becomes a regression test. Attempted gaming is treated as useful output — the agent is fuzzing our definition of success.
  • Candidate isolation: container/VM, no evaluator source, no hidden data, no per-case promotion scores, no secrets; aggregate metrics only for adversarial environments. Evaluator executes candidate artifacts inside the sandbox, never with evaluator privileges (Review F3).
  • Evaluation of evaluators: periodically sample good/medium/bad/odd-Pareto candidates for human review; track metric↔human correlation, especially for 3D assets, voice, pedagogy, research reports.

Review findings Reviewed 2026-08-30

Verdict: the thesis (evaluate() is the product) and the architecture (agent never controls the evaluator) are right. The corrections below are folded into the roadmap above.

#SeverityFindingResolution
F1HighWrong first environment. The plan skips the working loop already in this repo, and calls 3DGS "short loops" — but a real benchmark (10+ scenes × 3 seeds × full training) is hours per experiment on a 4070. Cheapest-loop-first maximizes iterations on the harness, which is the actual Phase-0/1 product.nanochat trainer = env #0 (validates the contract against a known-good loop); LevelForge (CPU, seconds–minutes) before 3DGS.
F2HighPromotion is underspecified. Pareto frontiers + robust scores + hidden sets never say who picks the champion. Karpathy's loop works because val_bpb is one number; the first time two candidates don't dominate each other, keep/revert is undefined.v1: hard gates → one declared promotion_score per env (lexicographic/scalar). Pareto frontier is an archive, not the promotion rule.
F3HighIsolation weaker than assumed. Path-based mutable/immutable is not a security boundary: run_candidate.sh is candidate-controlled, so the evaluator executing it runs candidate code with evaluator privileges. "Where practical" is not a sandbox policy on a single shared box.Sandbox is a Phase 0 deliverable with a test proving the candidate can't read evaluator/hidden paths or reach the network.
F4MediumStatistics budget math. Seeds × scenario suites × hidden promotion multiplies each experiment 10–50×; on one 4070 that's a handful of 3DGS experiments per night.Measure baseline seed variance per env first; define minimum detectable effect; use paired seeds vs champion + sequential early stopping.
F5MediumEvaluator versioning missing. §Eval-of-evaluators commits to revising evaluators, but nothing ties historical scores to an evaluator version — leaderboards silently become incomparable.eval_version + dataset_hash on every record; re-baseline champion on evaluator change.
F6MediumUniversal contract designed too early. The full research.yaml schema is speculation before any environment runs.Phase 0 ships only what env #0 needs; the general schema is extracted from evidence after two working adapters (Phase 1 task).
F7MediumGround truth is the hidden cost of the tier list. Driftport, COI, TaxLens corpora, and market snapshots are human-annotation-hours, not GPU-hours; the plan treats them as free.Tiering explicitly weights ground-truth acquisition cost; annotation work scheduled as project tasks, not assumed.
F8LowMulti-agent org & meta-research premature. The plan gestures at this; make it binding.Hard non-goal for Phases 0–1. Earliest high-leverage "meta" work: experiment-history summarization into researcher context (the program.md analog).
F9LowLevelForge v2 metrics are research problems. Pedagogical alignment and solution-diversity scoring are themselves open problems; gating v1 on them stalls the environment.v1 gates/metrics: solvability, difficulty error, instruction coverage. Diversity/pedagogy land as non-gating v2 metrics.

Verification

  • Phase 0 done when: an overnight env-0 run on this repo produces a JSONL history, leaderboard, and a champion ≥ baseline val_bpb, with revert restoring the champion bit-exact, and sandbox tests proving candidate isolation.
  • Phase 1 done when: LevelForge and 3DGS both run on the shared contract; each has a measured baseline σ, a THREATS.md with passing exploit regression tests, and ≥ one promoted improvement that survives the hidden promotion corpus.
